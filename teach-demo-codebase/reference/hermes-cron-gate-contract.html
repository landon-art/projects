Hermes cron: gate & delivery contract

Cheat sheet. What the scheduler reads, in order. Source: Cron docs, PR #12373.

Pipeline per tick

pre-run script ──► gate parse ──► LLM run (+skills) ──► delivery
   exit code        last stdout      final response      [SILENT]?

1. Pre-run script

Script resultScheduler does
exit 0, last non-empty stdout line is JSON {"wakeAgent": false}Skip LLM. No tokens, no delivery. Output logged as silent tick.
exit 0, anything else (no JSON, wakeAgent=true, {"wakeAgent": 0}, missing key)Fail-open: wake agent. Script stdout becomes context for the prompt.
non-zero exit or timeoutError alert delivered. Cannot be silenced.

Only strict boolean false gates. Earlier lines are free for logging.

2. LLM run

  • Skills load first, in listed order (skills=["a","b"]). Prompt layers on top.
  • SOUL.md is system-prompt slot #1 for every run.
  • Output persisted: ~/.hermes/cron/output/{job_id}/{timestamp}.md

3. Delivery

Final responseDelivered?
contains [SILENT], run succeededNo. Still saved locally.
run failedYes, always. Marker ignored.
otherwiseYes.

Two markers, two layers. Never mix.

{"wakeAgent": false}[SILENT]
Who emitsPre-run scriptThe LLM
Where readLast stdout line, before LLMFinal response, after LLM
Saves tokens?YesNo (LLM already ran)
TrapNon-JSON text = wakeScript text containing [SILENT] can get echoed by LLM and silence a real alert

Gate template (bash)

#!/usr/bin/env bash
state=$(probe)            # any logging OK above
if healthy; then
  echo '{"wakeAgent": false}'; exit 0
fi
echo "ALERT: $state"      # plain text = agent wakes, sees this
exit 0                    # keep 0; non-zero = error alert path
